# Доклад: нейросетевой суррогат CRM-грунта Chrono::FSI

## Резюме

Цель проекта — проверить, может ли нейросеть заменить часть вычислений Chrono::FSI для задачи погружения плиты в грунт. Chrono решает CRM-модель грунта методом SPH на GPU. Сеть получает историю целевой частицы и её соседей и предсказывает изменение состояния за один кадр.

Есть два разных режима. Текущий эксперимент — полный авторегрессионный прогноз всего грунта. Целевой режим проекта — гибрид Chrono + нейросеть: сеть заменяет только выбранную часть расчёта, а Chrono продолжает считать остальные физические величины. Полный прогноз оказался медленнее Chrono и накапливает ошибку на движущихся частицах, но гибридная схема пока не реализована и не измерялась.

В этом документе технические сокращения расшифрованы при первом упоминании. Chrono::FSI означает модуль Project Chrono для взаимодействия жидкости, твёрдых тел и грунта. CRM означает Continuous Representation Model, то есть модель грунта как сплошной среды. SPH означает Smoothed Particle Hydrodynamics, то есть метод сглаженных частиц. GPU означает графический процессор. CPU означает центральный процессор. MLP означает многослойный перцептрон. GRU означает рекуррентную ячейку с управляемыми воротами. RMSE означает корень из среднего квадрата ошибки. MSE означает средний квадрат ошибки. Holdout означает отложенный запуск, который не использовался для обновления весов.

## 1. Физическая задача и данные

Моделируется беваметр: круглая плита диаметром 0,3 м погружается в грунт со скоростью 5 мм/с на глубину 20 мм. Грунт — упругопластическая CRM-модель Chrono::FSI, дискретизированная методом SPH.

Один запуск содержит 4 секунды погружения: 200 кадров с интервалом dt = 0.02 s. Начальные 0,5 секунды оседания под гравитацией в датасет не входят.

Для частицы (i) её состояние в кадре (t) обозначим

\[
s_i^t=(\mathbf r_i^t,\mathbf v_i^t,\rho_i^t,\boldsymbol\sigma_i^t,p_{c,i}^t,E_{v,i}^t,S_{v,i}^t)\in\mathbb R^{16},
\]

где \(\mathbf r=(x,y,z)\), \(\mathbf v=(v_x,v_y,v_z)\), а \(\boldsymbol\sigma\) содержит шесть компонент напряжения. Интервал между кадрами:

\[
\Delta t=0{,}02\ \text{с}.
\]

| Параметр | Значение |
|---|---|
| Угол трения phi | 25, 30, 35, 40, 45 градусов |
| Сцепление | 0, 500, 1000, 2000, 5000 Па |
| Всего запусков | 25 |
| Обучение / holdout | 21 / 4 запуска |
| Грунт | 46 464 частицы |
| Плита | 410 маркеров |
| Стенки | 24 855 маркеров |
| Интервал кадров | 0,02 с |

Строка частицы содержит 16 величин:

~~~text
x,y,z                    положение, м
vx,vy,vz                 скорость, м/с
rho                      плотность, кг/м³
p11,p22,p33              нормальные напряжения, Па
shear12,shear13,shear23  касательные напряжения, Па
pc,Ev,Sv                 дополнительные переменные состояния солвера
~~~

В доступном локальном прогоне rho постоянно равно 1600 кг/м³, а pc, Ev, Sv равны нулю. Нулевая ошибка этих столбцов не доказывает, что сеть научилась их физике.

## 2. Входы сети

Для каждой целевой частицы используется окно из 9 кадров: 8 предыдущих и текущий.

То есть сеть видит последовательность \(t-8,\ldots,t\), всего \(H=9\) моментов времени.

Центральная частица имеет 18 признаков на кадр:

~~~text
3 скорости + 10 признаков состояния + 3 one-hot типа + 2 параметра запуска
~~~

Состояние — это rho, шесть напряжений и pc/Ev/Sv. Тип кодируется как грунт, плита или стенка. Параметры запуска — phi и cohesion.

Для каждого из K = 256 соседей добавляются 7 признаков ребра:

~~~text
dx,dy,dz       относительное положение
distance       расстояние
dvx,dvy,dvz    относительная скорость
~~~

Соседи выбираются динамически на каждом шаге по текущим координатам через cKDTree. История соседа собирается по тому же ID, поэтому частица не заменяется другой частицей, которая раньше была ближе.

Для соседа \(j\) добавляется относительный вектор

\[
\mathbf e_{ij}^t=\left(\mathbf r_j^t-\mathbf r_i^t,\;\|\mathbf r_j^t-\mathbf r_i^t\|,\;\mathbf v_j^t-\mathbf v_i^t\right)\in\mathbb R^7.
\]

Выбор соседей можно записать как \(\mathcal N_i^t=\operatorname{KNN}_{256}(\mathbf r_i^t)\).

## 3. Архитектура

~~~text
история центра (9 × 18)       → MLP → GRU → вектор 256
история соседа (9 × 25)       → MLP → GRU → вектор 256
центр + сосед                 → MLP сообщения → 256
сообщения всех соседей         → среднее + максимум
центр + агрегаты               → декодер → 16 изменений состояния
~~~

Сеть не передаёт сообщения между соседями и не зависит от порядка соседей. Она делает один раунд агрегации.

При hidden = 256 сеть содержит 1 200 656 обучаемых параметров. Это одна общая сеть для всех частиц. Adam обновляет полный набор параметров на каждом шаге.

Сеть предсказывает не абсолютное состояние, а:

~~~text
delta = state(t + dt) - state(t)
~~~

Затем delta прибавляется к текущему состоянию.

В формулах это выглядит так:

\[
\Delta s_i^{t\to t+1}=s_i^{t+1}-s_i^t,
\qquad
\hat s_i^{t+1}=s_i^t+\widehat{\Delta s}_i^{t\to t+1}.
\]

История центра и каждого соседа кодируется отдельно, затем сообщения объединяются:

\[
\mathbf h_i=\operatorname{GRU}(\operatorname{MLP}(\mathbf x_i^{t-8:t})),
\quad
\mathbf h_{ij}=\operatorname{GRU}(\operatorname{MLP}([\mathbf x_j,\mathbf e_{ij}]^{t-8:t})),
\]

\[
\mathbf m_{ij}=\operatorname{MLP}([\mathbf h_i,\mathbf h_{ij}]),\quad
\bar{\mathbf m}_i=\frac1{|\mathcal N_i|}\sum_{j\in\mathcal N_i}\mathbf m_{ij},\quad
\mathbf m_i^{\max}=\max_{j\in\mathcal N_i}\mathbf m_{ij}.
\]

Итоговый выход сети:

\[
\widehat{\Delta s}_i=\operatorname{MLP}([\mathbf h_i,\bar{\mathbf m}_i,\mathbf m_i^{\max}]).
\]

## 4. Обучение

| Настройка | Значение |
|---|---:|
| Ширина hidden | 256 |
| Соседи K | 256 |
| История | 8 предыдущих + текущий кадр |
| Batch | 32 целевые частицы |
| Начальный lr | 1e-4 |
| Всего обновлений | 50 000 |
| Статистика нормализации | 40 случайных пакетов |
| Валидация | 16 случайных пакетов |
| Устройство | Tesla T4, CUDA |

Обычная одношаговая MSE в основном видит спокойные частицы. В тестовом rollout только 4,84% сравнений имели истинную скорость не ниже 1 мм/с, но на них пришлось 99,35% суммы квадратов ошибки координат.

Перед обучением каждый признак приводится к общей шкале:

\[
\tilde x_d=\frac{x_d-\mu_d}{\sigma_d},
\qquad
\mu_d=\frac1n\sum_q x_{q,d},
\qquad
\sigma_d=\sqrt{\frac1n\sum_q(x_{q,d}-\mu_d)^2}.
\]

Функция ошибки — средний квадрат нормализованного промаха:

\[
\mathcal L_{\mathrm{MSE}}=\frac1{BD}\sum_{i=1}^{B}\sum_{d=1}^{D}
\left(\widehat{\widetilde{\Delta s}}_{i,d}-\widetilde{\Delta s}_{i,d}\right)^2,
\qquad D=16.
\]

Веса обновляются по градиенту: \(\theta\leftarrow\operatorname{Adam}(\theta,\nabla_\theta\mathcal L)\).

## 5. Результаты полного rollout

Проверены 10 шагов phi30_c500, кадры 9–18, то есть 0,2 секунды физики. Первый вход был истинным, следующие состояния сеть подавала сама себе.

| Метрика положения | Значение |
|---|---:|
| RMSE всех частиц и кадров | 0,1235 мм |
| 95-й процентиль | 0,0366 мм |
| 99-й процентиль | 0,1567 мм |
| Максимальная ошибка | 9,422 мм |
| RMSE на кадре 18 | 0,2388 мм |

Для частиц с истинной скоростью не ниже 1 мм/с:

| Метрика | Кадр 9 | Кадр 18 |
|---|---:|---:|
| RMSE положения | 0,021 мм | 1,069 мм |
| RMSE скорости | 1,81 мм/с | 12,11 мм/с |
| Предсказанная скорость / истинная | 92% | 47% |

Сеть лучше нулевого прогноза скорости: 8,27 против 13,21 мм/с. Но при авторегрессии она всё сильнее недооценивает движение.

Здесь rollout означает последовательный самостоятельный прогноз: после первого шага сеть получает уже свои предыдущие состояния. Это главный режим, где проявляется накопление ошибки.

Давление под плитой:

| Сравнение | Ошибка |
|---|---:|
| Сеть против формулы на истинных частицах | 1,02% |
| Формула на истинных частицах против кривой солвера | 16,80% |
| Сеть против кривой солвера | 17,04% |

Почти всё расхождение давления с эталоном возникает из самой формулы оценки давления.

## 6. Скорость

На Tesla T4 полный прогноз одного кадра занимает около 54,5 с, то есть около 45 минут на секунду физики.

| Этап | Время | Доля |
|---|---:|---:|
| KD-tree и поиск соседей | 0,663 с | 1,2% |
| Сбор историй | 10,728 с | 19,7% |
| Нормализация | 6,081 с | 11,2% |
| Передача на GPU | 2,939 с | 5,4% |
| Нейросеть | 33,631 с | 61,7% |

Поиск соседей больше не является главным узким местом. История соседа повторно обрабатывается для каждого центра: получается около 11,9 млн соседских историй на кадр. Полный rollout примерно в 11 раз медленнее сохранённого времени Chrono.

## 7. Причина накопления ошибки

При обучении сеть видит истинные истории:

~~~text
истинная история → прогноз следующего кадра → сравнение с истиной
~~~

При rollout она видит собственные ошибки:

~~~text
истинная история → прогноз → прогноз из предыдущего прогноза → накопленная ошибка
~~~

Ошибка скорости меняет координаты, координаты меняют соседей и относительные признаки, а ошибочные напряжения попадают в GRU. Следующий шаг получается на состоянии, которого почти не было в обучающей выборке.

Кроме того, положение и скорость предсказываются независимо. Полезно добавить ограничение:

~~~text
delta_position ≈ dt × (current_velocity + next_velocity) / 2
~~~

## 8. Следующий тест: teacher forcing

Добавлен флаг --teacher_forced. Перед каждым предсказанием сеть получает настоящую историю до текущего момента. Следующий кадр скрыт и используется только как цель. Это измеряет чистую одношаговую ошибку без накопления прогнозов модели.

~~~bash
python -u -m surrogate.particle.rollout \
  --ckpt checkpoints/particle_history_k256_h8_w256/best.pt \
  --data_dir data --tag phi30_c500 --start_frame 8 --steps 10 \
  --batch 32 --device cuda --neighbor_workers 4 --teacher_forced \
  --save_particles --plot \
  --out checkpoints/particle-eval-w256/teacher_forced.npz
~~~

Если teacher-forced ошибка мала, а обычный rollout плох, проблема в накоплении. Если она уже велика — проблема в данных, нормализации, выборке, архитектуре или обучении. Если TRAIN хороший, а holdout плох — проблема в обобщении.

### Фактически полученный результат

Проверка выполнена на том же отложенном запуске phi30_c500 и тех же десяти кадрах. В режиме teacher forcing перед каждым предсказанием использовалась истинная история, а предсказывался только следующий кадр.

| Показатель | Самостоятельный прогноз | Teacher forcing |
|---|---:|---:|
| Ошибка положения на первом шаге | 0,005 мм | 0,005 мм |
| Ошибка положения на десятом шаге | 0,239 мм | 0,009 мм |
| Ошибка скорости по координатам x | 0,862 мм/с | 0,332 мм/с |
| Ошибка скорости по координатам y | 0,843 мм/с | 0,247 мм/с |
| Ошибка скорости по координатам z | 1,368 мм/с | 0,394 мм/с |
| Ошибка давления против оценки на истинных частицах | 1,02% | 0,60% |
| Ошибка давления против кривой решателя | 17,04% | 17,30% |

Этот результат меняет диагноз. Одношаговая нейросеть действительно умеет предсказывать следующее состояние на правильной истории. За десять шагов ошибка положения в режиме teacher forcing остаётся почти постоянной, тогда как при самостоятельном прогнозе она увеличивается примерно в 48 раз: с 0,005 до 0,239 мм.

Следовательно, добавление данных само по себе не является первым исправлением. Главная проблема находится в устойчивости авторегрессионного режима: модель обучалась на истинных историях, а используется на историях, загрязнённых её собственными ошибками.

## 9. План исправления

1. Считать teacher-forced проверку обязательной метрикой и запускать её на holdout и TRAIN.
2. Посчитать долю активных частиц во всех запусках.
3. Добавить взвешивание ошибки по активности частиц: увеличить вклад примеров с большим истинным перемещением или скоростью.
4. Обучать на коротких собственных историях через scheduled sampling, то есть постепенно заменять истинные входы прогнозами модели, или через replay, то есть повторное обучение на заранее собранных прогнозных историях.
5. Добавить кинематический штраф для согласованности положения и скорости.
6. Считать нормализацию по большему числу кадров и частиц, не удаляя редкие физические скачки.
7. Только потом сравнивать новые размеры и архитектуры.
8. Реализовать гибрид Chrono + сеть и измерять только заменяемую сетью часть расчёта.

Простое добавление похожих спокойных кадров может усилить перекос в пользу неподвижных частиц.

## Вывод

Сеть умеет предсказывать небольшие изменения и лучше нулевого прогноза на первом шаге, но не сохраняет движение активных частиц в самостоятельной траектории. Полная замена Chrono текущей архитектурой не оправдана. Следующий решающий эксперимент — teacher-forced оценка; перспективная конечная система — гибрид, в котором Chrono сохраняет физическую интеграцию, а сеть заменяет отдельную измеримую часть расчёта.
