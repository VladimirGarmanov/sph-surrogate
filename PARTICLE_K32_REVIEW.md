# Проверка эксперимента K32 / три кадра истории соседей

Дата: 2026-09-08. Проверка кода и локальных данных; нового обучения и
замера K32 на CUDA ещё нет.

## Что сравниваем

`scripts/train_particle_k32.sh` и `scripts/train_particle_w256.sh` используют
одинаковые параметры обучения, кроме K=32 вместо 256 и последних трёх
кадров истории соседей вместо девяти. Центр сохраняет девять кадров;
соседи выбираются по текущему кадру, их постоянные ID отслеживаются по
последним кадрам. Сохранены `full_frames`, число эпох, горизонт 5,
`input_noise_std=0.05`, batch=32, hidden=256, holdout, seed и расписания
обучения и валидации. Каждый эксперимент начинается в новом каталоге
со своей статистикой нормализации TRAIN.

Это одна совместная проверка сокращения соседства и его истории. Чтобы
разделить влияние этих двух изменений на качество, потребуются отдельные
контроли K32 / девять кадров и K256 / три кадра.

## Что известно о скорости

Старый файл `checkpoints/particle-eval-h5-noise-20260908-134740/rollout.log`
содержит 52.436 с/кадр: network 33.6816, gather 9.4781, normalize 5.3402,
to_device 2.8377, поиск соседей 0.6125 с. Это профиль с синхронизацией GPU
между этапами, поэтому нужен повторный замер без `--profile`.

Число шагов истории соседей равно 46 464 × K × длина истории:
107 053 056 → 4 460 544, сокращение в 24 раза. Центральные истории и
декодер сохраняются, message MLP обрабатывает в восемь раз меньше соседей,
а число GPU-пакетов при batch=32 остаётся 1452 на кадр. Поэтому оценку
2.84 с/кадр нельзя считать результатом измерения или гарантией.

Команды обучения и rollout приведены в [README](README.md).
Сравнивать нужно на одной GPU с одинаковыми batch, потоками поиска,
кадрами и режимом измерения. Первые десять шагов — короткая проверка;
для вывода о качестве нужны длинные rollout всех holdout, ошибки
положений и остальных состояний частиц, давление под плитой.

## Что известно о соседстве

Локально доступны данные `phi35_c1000`. Команда:

```bash
python scripts/particle_neighbors.py --tag phi35_c1000 \
  --frames 0 100 199 --neighbors 32 64 256 \
  --radii 0.024 0.04 0.08 --samples 2048
```

На 6144 выбранных центрах радиус 0.04 м даёт в среднем 29.0 соседей;
p5 / p50 / p95 числа соседей — 26 / 29 / 32. Расстояния до K-го соседа:

| K | p50, м | p95, м | Максимум, м |
|---|---:|---:|---:|
| 32 | 0.04003 | 0.04469 | 0.07404 |
| 64 | 0.04898 | 0.05058 | 0.09252 |
| 256 | 0.08000 | 0.08523 | 0.13466 |

На всех 46 464 центрах кадров 0 / 100 / 199 хотя бы один маркер плиты
попал в K32 у 556 / 499 / 518 частиц, в K256 — у 1544 / 1610 / 1837.
Среди центров в пределах 0.04 м от ближайшего маркера плиты
(520 / 341 / 416 частиц) ни один не потерял все маркеры плиты при K32.
Это геометрическая проверка трёх кадров одного материала; она не доказывает
достаточность K32 для других кадров, материалов или ошибочного rollout.
Принудительное добавление дальних маркеров плиты пока не вводится.

Ориентир 30–60 соседей в NN_SPEC относится к историческому плану GNS.
У ParticleNet нет нескольких раундов передачи сообщений; точный носитель
ядра исходного Chrono-запуска этими измерениями не устанавливается.
K32 остаётся гипотезой, которую нужно проверить по скорости и качеству.
