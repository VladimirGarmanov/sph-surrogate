# sph-surrogate

Нейросетевой суррогат CRM-грунта из Chrono::FSI.

**Подробное объяснение теории, каждого файла и самостоятельного запуска на
сервере — в [ML_GUIDE_RU.md](ML_GUIDE_RU.md).**

## Текущая модель: частица, соседи и история

Один пример — целевая частица, 256 ближайших соседей во всём кадре,
текущий и 8 предыдущих кадров этих же частиц. GRU обрабатывает истории,
модель объединяет информацию о соседях и предсказывает изменение всех
16 величин центра через 0.02 с. Кубов и halo в этом режиме нет.

```bash
# Измерить соседство и физический радиус до K-го соседа.
python scripts/particle_neighbors.py --tag phi35_c1000 --neighbors 128 256 512

# Полное обучение: каталог data должен содержать обучающие и holdout-прогоны.
python -m surrogate.particle.train --data_dir data --neighbors 256 --history_frames 8 --batch 32 --steps 20000

# Проверить самостоятельную прокрутку на отложенном материале.
python -m surrogate.particle.rollout --ckpt checkpoints/particle/best.pt --tag phi30_c500 --plot

# Продолжить с сохранёнными настройками, нормализацией и оптимизатором.
python -m surrogate.particle.train --resume checkpoints/particle/model.pt --steps 40000
```

`batch` — число целевых частиц, `neighbors` — соседей каждой из них.
`history_frames=8` означает 8 прошлых **плюс текущий**, всего 9 кадров.
Соседи выбираются сейчас, а их прошлое собирается по постоянным ID.

На единственном местном прогоне можно явно задать `--holdout ''` для
проверки кода. Тогда печатается `TRAIN_DIAGNOSTIC`, сохраняется `model.pt`,
но не выбирается `best.pt`: такая проверка не оценивает обобщение.

Тесты: `python -m unittest discover -s tests -v`.
Новая архитектура обучена на сервере 20 000 обновлений. Проверены первые
10 предсказанных кадров `phi30_c500`; длинные траектории и остальные
отложенные материалы пока не оценены. Числа — в `RESULTS.md`.

### Дообучение на собственных прогнозах

`python -m surrogate.particle.finetune` продолжает обучение существующих
весов на историях, которые сеть сама получила в полной прокрутке грунта.
Каждый цикл заново собирает эти состояния, отводит 25% обновлений чистым примерам
и проверяет результат на фиксированном отложенном окне. Градиент проходит
через очередной переход; вся траектория собирается без градиентов.

Команды короткой проверки, основного запуска и продолжения, а также смысл
`best.pt` и метрик — в [docs/PARTICLE_FINETUNE_RU.md](docs/PARTICLE_FINETUNE_RU.md).
Запускать рабочий эксперимент нужно на сервере с обученными весами и данными.

### Сравнение каждой частицы с солвером и замер времени

Для уже обученной модели на сервере:

```bash
python -u -m surrogate.particle.rollout \
  --ckpt checkpoints/particle_history_k256_h8/best.pt \
  --data_dir data --tag phi30_c500 --steps 10 --batch 32 --device cuda \
  --save_particles --profile --plot \
  --out checkpoints/particle_history_k256_h8/particles_phi30_c500_10.npz

python -m surrogate.particle.compare \
  --result checkpoints/particle_history_k256_h8/particles_phi30_c500_10.npz
```

`--save_particles` сохраняет все 16 предсказанных и эталонных величин
каждой частицы. `--profile` разделяет время поиска соседей, подготовки
данных, передачи на GPU и работы сети. Начальные истинные кадры не
включаются в массивы предсказаний. Переобучение не требуется.

Выгрузить таблицу для выбранной частицы можно на сервере или на Mac
после скачивания **только результата**:

```bash
python -m surrogate.particle.compare \
  --result checkpoints/particles_phi30_c500_10.npz \
  --particle_ids 123 --csv checkpoints/particle_123.csv
```

Строка CSV: кадр, ID частицы, параметр, единица, значение солвера,
прогноз, знаковая и абсолютная ошибки. Полные результаты хранятся
в `.npz`; `compare` также пишет сводный JSON с RMSE, процентилями и
номерами частиц с наибольшей ошибкой положения. Веса для `compare` не нужны.
Подробный разбор новых функций и таймеров — в главе 23 `ML_GUIDE_RU.md`.

## Предыдущая версия GNS

Ниже — прежние файлы, команды и решения, к которым относятся результаты
старых экспериментов в `RESULTS.md`. Их веса несовместимы с новой моделью.

## Структура

```
surrogate/
  config.py     все гиперпараметры (каждое поле = флаг CLI у train)
  data.py       Run: ленивые memmap'ы трёх .npy, порядок узлов soil, plate, wall
  graph.py      рёбра через cKDTree, признаки узлов/рёбер, цели (конечные разности)
  normalize.py  mean/std по узлам, рёбрам, целям; сохраняются в чекпоинт
  dataset.py    Dataset: кадр -> граф; шум во входах; случайный кроп-куб
  model.py      GNS: encoder -> N слоёв message passing -> decoder (13 выходов)
  train.py      обучение на один шаг, валидация на отложенных прогонах
  rollout.py    авторегрессия, длина устойчивого прогона, давление на плите, замер скорости
scripts/
  neighbors.py  шаг 1: среднее число соседей при разных радиусах
```

## Команды

```bash
# 1. радиус соседей (цель: 30-60 в колонке all)
python scripts/neighbors.py --tag phi35_c1000 --frame 100 --radii 0.03 0.04 0.05

# 2-3. обучение; отложенные прогоны задаются через --holdout
python -m surrogate.train --data_dir data --radius 0.04 --steps 20000 --out_dir checkpoints/gns

# 5. сначала проверить оценку давления на кадрах солвера (знак p33!)
python -m surrogate.rollout --ckpt checkpoints/gns/best.pt --tag phi30_c500 --calibrate

# 4-6. авторегрессия + кривая давление-осадка + замер скорости
python -m surrogate.rollout --ckpt checkpoints/gns/best.pt --tag phi30_c500 --plot
```

## Решения, которых нет в NN_SPEC

- **Скорость на входе — конечная разность позиций**, а не колонка `v_*` из
  солвера. При авторегрессии скорости солвера нет, есть только свои позиции;
  учить на одном, а кормить другим нельзя.
- **Плотность тоже предсказывается** (выходов 13, а не 12): она входной
  признак, значит при прокрутке её надо откуда-то брать.
- **Кроп-кубы при обучении.** Полный кадр — 72k узлов и ~2-3M рёбер, backprop
  через 6 слоёв на это не влезает ни в T4, ни в Mac. Учимся на случайных кубах
  `crop_half`, с вероятностью `crop_near_plate` центрируем под плитой. Узлы у
  границы куба (`crop_halo`) — только вход, не цель.
- **Рёбра только в грунт** (`edges_to_static=False`): плита и стенки
  посылают сообщения, но не принимают — их никто не предсказывает.
- **Шум для состояния масштабирован от изменения за шаг**, не от std самого
  признака. Иначе цель вырождается в «убери шум».
- Rollout идёт по полному кадру; на Mac это несколько ГБ на шаг. Если не
  влезает — уменьшать `hidden` или запускать на EC2.
